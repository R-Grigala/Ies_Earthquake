# Push ნოტიფიკაციები (დაგეგმილი)

**სტატუსი:** 🔜 არ არის იმპლემენტირებული

## რატომ არ არის პირველ ვერსიაში

Push ნოტიფიკაცია მხოლოდ კლიენტის მხარეს ვერ კეთდება — საჭიროა სერვერი, რომელიც
ახალ მოვლენას აღმოაჩენს და შეტყობინებას გააგზავნის. სანამ ბექენდის მხარე არ
არსებობს, პარამეტრებში გადამრთველს არ ვამატებთ, რომ მომხმარებელს არ შევპირდეთ
ფუნქციონალი, რომელიც არ მუშაობს (GNSMC-ში სწორედ ასეთი switch იყო).

## საჭირო ნაბიჯები

1. `expo-notifications` და `expo-device` დამატება.
2. კლიენტში ნებართვის მოთხოვნა და Expo push token-ის მიღება.
3. ბექენდზე ენდპოინტი token-ის რეგისტრაციისთვის, მომხმარებლის ფილტრებთან ერთად
   (მინიმალური მაგნიტუდა, რეგიონი).
4. ბექენდზე ახალი მოვლენების მონიტორინგი და Expo Push API-ით გაგზავნა.
5. აპში ნოტიფიკაციაზე დაჭერის დამუშავება — გახსნა `/event/[id]`-ზე.
6. პარამეტრებში გადამრთველი და ზღვარის არჩევანი.

## შუალედური ვარიანტი

სანამ სერვერი არ არის, ალტერნატივაა ლოკალური შემოწმება: აპი აქტიური რომ არის,
`useEarthquakes()`-ის refetch-ის დროს შეიძლება შედარება ბოლო ნანახ `id`-სთან და
in-app ბანერის ჩვენება. ეს არ ცვლის push-ს (დახურული აპი შეტყობინებას არ მიიღებს),
მაგრამ არ საჭიროებს ბექენდის ცვლილებას.
