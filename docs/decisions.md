# ტექნიკური გადაწყვეტილებები

## სტეკი

| გადაწყვეტილება | მიზეზი |
| --- | --- |
| TypeScript | API-ს პასუხის ფორმა არასტაბილურია (string რიცხვები, `null`-ები); ტიპები ამ საზღვარს იცავენ |
| expo-router | ფაილებზე დაფუძნებული მარშრუტები, deep link `-/event/[id]`-ზე უფასოდ |
| TanStack Query | ქეში, auto-refetch, loading/error მდგომარეობები — ეს ლოგიკა ეკრანებიდან გამოდის |
| react-native-maps | გამოცდილი არჩევანი GNSMC-იდან, Expo-სთან თავსებადი |
| i18next | იგივე მიდგომა, რაც GNSMC-ში მუშაობდა |

state-მენეჯერი (Redux/Zustand) არ დაემატა: სერვერის მდგომარეობას Query ფარავს,
ლოკალურს — ორი პატარა კონტექსტი.

## GNSMC-იდან გამოსწორებული ხარვეზები

წინა პროექტი [R-Grigala/GNSMC](https://github.com/R-Grigala/GNSMC) ორიენტირად
გამოვიყენეთ. შემდეგი პუნქტები განზრახ შეიცვალა:

| GNSMC | ახლა |
| --- | --- |
| API ტოკენი და ngrok URL კოდში ჩაწერილი | `.env` / `EXPO_PUBLIC_*` ცვლადები |
| `fetch` ეკრანების შიგნით, ქეშის გარეშე | `src/api` + TanStack Query |
| `formatData` ლოკალურ დროს აჩვენებდა, წარწერა კი „UTC" | `formatUtcDateTime()` და `formatLocalDateTime()` ცალკე |
| მარკერების `key` — მასივის ინდექსი | `event.id` |
| მარკერის აიკონები სერვერიდან იტვირთებოდა (`.gif`/`.png`) | სისტემური მარკერები, ფერი და ზომა კოდში |
| ცარიელი პასუხი და შეცდომა ერთი ეკრანი იყო | ცალკე empty და error მდგომარეობები |
| თემის გადართვა event bus-ით | React context + AsyncStorage-ში შენახვა |
| ნოტიფიკაციების არაფუნქციური switch | გადამრთველი მხოლოდ რეალურ იმპლემენტაციასთან ერთად |
| შერეული სტრუქტურა (`screens/`, `components/`, `data/`) | `app/` მარშრუტებისთვის, `src/` ლოგიკისთვის |

## რაც სპეციალურად შენარჩუნდა

- ქვედა ტაბებით ნავიგაცია და მიწისძვრების სია მთავარ ეკრანად.
- რუკის საწყისი ცენტრი და მასშტაბი (42.0186, 43.9911, delta 10).
- მაგნიტუდის ფერების სქემა (>5 წითელი, >4 ნარინჯი, >3 იისფერი).
- მოვლენის ასაკის სამი დონე (7 დღე / 3 თვე / უფრო ძველი).
- ორენოვნება ka/en, ქართული ძირითადად.
